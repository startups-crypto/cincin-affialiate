# CinCin Partners — локальная тестовая сборка

Telegram-бот на русском. Данные сохраняются в SQLite на этом компьютере; Google Sheets служит отчётом для менеджеров. Код и шаблон настроек находятся в репозитории; рабочие ключи и пользовательская база в него не входят.

## Настройка и запуск

Нужен Python 3.11 или новее. Все доступы и ID указываются в **одном файле `config.toml`**. Код читает их через `settings.py`; менять токены и ID в исходниках не нужно.

1. Создайте окружение и установите зависимости:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

2. Скопируйте `config.example.toml` в `config.toml` и заполните поля по комментариям. Пошаговая инструкция получения доступов — в [SETUP.md](SETUP.md).
3. Проверьте подключения: `.venv/bin/python check_access.py`.
4. Запустите `.venv/bin/python bot.py`. На macOS также можно открыть `Start.command`. Для остановки нажмите Ctrl+C. После изменения настроек перезапустите бота.

Владелец назначается по `telegram.owner_ids` в `config.toml`. Чтобы сменить владельца, поменяйте этот список и перезапустите бота: права прежних владельцев, которых больше нет в списке, будут сняты. Менеджеры назначаются через панель «Сотрудники».

Компьютер должен быть включён, подключён к интернету и не спать. Одновременно запускается один экземпляр бота. Если переносите бот на сервер, сначала остановите локальный экземпляр.

## Что работает

- Принятие правил, подтверждение нескольких каналов кодом в описании.
- Приём новых публичных видео с подтверждённого канала в течение 24 часов с публикации и после принятия правил.
- Проверка длительности до 180 секунд. Сам формат Shorts и наличие баннера весь ролик проверяет менеджер. Персональная ссылка автора проверяется автоматически при подаче, каждые 15 минут, при одобрении и перед подготовкой выплаты.
- Обновление статистики каждые 15 минут, уведомления о новых оплачиваемых порогах.
- Отдельные блоки по 100 000 просмотров, $5 за блок, 60 дней учёта. Финальное округление при остатке от 90 000.
- Общая таблица: обзор авторов, выплаты и отдельная вкладка каждого автора. Внесённые вручную изменения таблицы не меняют начисления в базе.
- Роли владельца и менеджера, проверка контента, причины отказов, переписка текстовыми сообщениями через бота.
- Проверка контрольной суммы адреса TRON, хранение кошелька, фиксация подготовленной суммы и реквизитов выплаты.
- Выплаты от $20 с 5 по 10 число, только за предшествующие месяцы по Москве. Ручной перевод, уникальный хэш транзакции, история; новые начисления после выплаты сохраняются.
- Условия карточной программы: $10 за подтверждённое оформление карты плюс 0,1% от оборота по всем доступным операциям карт, открытых по партнёрской ссылке автора. CPA, процент от оборота и просмотры суммируются для минимальной выплаты $20. Срок 60 дней относится только к просмотрам. Срок получения процента отдельно пока не установлен.
- Автоматический импорт комиссий из Tracknow каждые 60 секунд и при открытии баланса. Только кампания из `tracknow.campaign_id` и известные правила card_issued / card_turnover, только привязанные affiliateId. APPROVED и PAID зачисляются один раз; HOLD/PENDING/REVISION/PROCESSING и TEST показаны отдельно. При отзыве подтверждения вносится корректировка. Фактический перевод автору регистрируется только в локальной истории выплат, статус PAID в Tracknow сам по себе не списывает баланс бота.
- В балансе три отдельные строки, кнопки детализации и история последних событий. Для каждого источника: начислено за всё время, выплачено, остаток. Те же графы в Google Sheets. Доли цента по обороту накапливаются до округления общей комиссии.
- Кнопка «Партнёрская ссылка» создаёт новый аккаунт Tracknow по email, без рекламных писем и отправки пароля, и сохраняет уникальный affiliateId. Существующие аккаунты автоматически по email не присваиваются: после проверки владелец использует /bindaffiliate TELEGRAM_ID AFFILIATE_ID. Привязать можно только аккаунт, уже состоящий в нашей кампании; перенос привязки между авторами запрещён.
- Журнал действий и отмена невыплаченных начислений при отказе по ролику. Блокировка автора по решению менеджера.
- Кнопка «Материалы» выдаёт три видео: баннер для СБП, баннер для криптовалюты и общий материал о карте. Старый логотип удалён из выдачи.

## Панель менеджера

Менеджеру и владельцу при запуске открывается отдельное меню с кнопками: «Авторы», «День выплат», «Подготовленные выплаты», «История выплат», «Обновить данные», «Таблица». Кнопка «Режим автора» возвращает обычное меню; «Панель менеджера» открывает рабочее место снова. Владельцу доступен раздел «Сотрудники» для назначения и снятия ролей.

«Авторы» — список по 8 записей с ID, никнеймом и балансом. В карточке: имя, остатки по трём источникам, сумма за прошлые месяцы, сколько роликов ждёт решения, кошелёк, история, таблица и кнопка переписки. Никнеймы обновляются из Telegram. Служебные аккаунты без авторской активности не включаются в список.

«День выплат» — авторы с суммой от $20 за прошлые месяцы и подготовленные, ещё не завершённые выплаты. Текущий месяц и суммы ниже минимума не входят в очередь. Отсутствие кошелька видно в карточке: менеджер может написать автору. Проверять контент можно в любой день; подготовка выплаты доступна 5–10 числа.

Рабочий путь: выбрать автора → «Проверить ролики» → одобрить или отклонить каждый ролик расчётного периода → «Подготовить выплату» → получить сумму и сохранённый кошелёк → перевести USDT вручную → «Перевод выполнен — указать хэш» → отправить хэш → «Подтвердить выплату». При отказе менеджер вводит причину обычным сообщением. Если есть непроверенные ролики расчётного периода, подготовка через панель не выполняется.

Подготовка резервирует конкретные начисления и реквизиты, но не убирает автора из очереди. Он исчезает из текущей очереди только после подтверждения перевода, если расчёт закрыт. Новые начисления сохраняются. Введённый хэш сам по себе ничего не списывает: нужна отдельная кнопка подтверждения. Хэш проверяется на формат и уникальность, без автоматического подтверждения в блокчейне.

На время работы автор закрепляется за менеджером на 30 минут, срок продлевается действиями проверки. Другой менеджер не может одновременно обработать его выплату. Доступна кнопка освобождения проверки; завершение и отмена подготовки снимают закрепление. История, действия и фактический менеджер сохраняются. Текстовые команды оставлены для совместимости, основной интерфейс их не требует.

## Tracknow

Ключ успешно проверен. Для локальной сборки выделена отдельная закрытая приостановленная кампания `cincin_banner_test`, ID 337. Настроены CPA $10 (40476) и отдельное процентное правило CPS 0,1% (40477), goalValue=card_turnover. Для CPA используется goalValue=card_issued. Новые конверсии по умолчанию имеют статус TEST. Карточный оборот — все доступные операции карт, открытых по партнёрской ссылке автора. Условия показаны в правилах, разделе «CPA и оборот», балансе, выдаче материалов и вкладке «Условия» Google Sheets. Клиент API реализован в `services.py`, документация сохранена в `docs/tracknow-openapi.json`.

Импорт реализован через полную пагинацию конверсий кампании и повторяемую сверку по стабильному ogId. Комиссия берётся из affiliateCommission в USD, а не пересчитывается повторно от уже рассчитанной комиссии. При ошибке API сохраняются предыдущие данные, показывается статус обновления, подготовка выплаты блокируется. Отмена комиссии отзывает подготовленную, ещё не завершённую выплату; уже выплаченная комиссия становится отрицательным остатком до компенсации будущими начислениями. Неизвестное правило, смена валюты или привязки операции требуют проверки, вместо автоматического начисления.

Остаётся подключить на стороне карточного сервиса передачу событий выпуска карты и всех доступных карточных операций с правильными автором, campaignId, payoutName/goal и уникальным ID операции. Тип кабинета GENERAL отклоняет REV_SHARE / TURN_OVER; используется поддерживаемая процентная модель CPS. Одно наличие правила CPS не подключает поток карточных операций. Чужие конверсии не импортируются. Удаление события без статуса отмены не считается отменой автоматически; источник должен передавать изменения статусов. При тайм-ауте создания партнёра не повторяйте регистрацию с другим email, пока владелец не проверит созданные аккаунты.

## Ограничения тестовой версии

- На границе 60 дней фиксируется последний успешный замер до срока: публичный API не даёт исторический счётчик на произвольную секунду. При простое компьютера часть просмотров может не попасть в расчёт. Послесрочные просмотры не добавляются.
- Недоступность видео снимает одобрение и отправляет уведомление менеджерам; отмена денег выполняется после ручного подтверждения удаления. Автоматическая проверка баннера и накрутки не реализована.
- При пропаже ссылки снимается одобрение и отменяется подготовленная выплата с этим роликом. Автор и менеджеры получают уведомление один раз при смене состояния. Повторные замеры не дублируют уведомление. После восстановления ссылки нужно повторное одобрение менеджера; ранее начисленная сумма сохраняется до решения менеджера. Автоматическая проверка сравнивает полный URL, включая идентификаторы автора и кампании; сокращённые и изменённые ссылки не принимаются.
- Диалоги доступны из карточки автора и кнопки ответа в уведомлении. Автоматические напоминания о платёжном окне пока не реализованы.
- На текущем этапе выплаты готовятся менеджером в установленное окно; автоматической отправки USDT нет.

## Настройки и проверка

Заполненный `config.toml` и база `data/` исключены из Git. Старые локальные `.env` и `secrets/` также исключены; бот больше не читает доступы из них. Для другого окружения достаточно заполнить один `config.toml`. Данные Google сервисного аккаунта находятся в его секции `[google_sheets.service_account]`; отдельный JSON-файл при запуске не нужен.

` .venv/bin/python -m unittest -v test_core test_partner test_links test_manager ` — проверки расчётов, повторных выплат, отказов, границ периода и импорта комиссий.

Перед использованием с реальными авторами нужны проверка всего сценария на тестовом канале и резервное копирование базы. При переносе на сервер база `data/` и заполненный `config.toml` переносятся отдельно от исходного кода.

## Railway

В Variables сервиса создайте `CONFIG_TOML` и вставьте всё содержимое заполненного `config.toml`. Бот умеет читать конфигурацию напрямую из этой переменной; размещать файл в репозитории не требуется. После сохранения выполните Redeploy. Подробности — в SETUP.md.

## Направления партнёрских ссылок

Кнопка «Партнёрская ссылка» предлагает CinCin Exchange (криптовалюта, кампания 338) и CinCin Cards (рубли РФ через СБП, кампания 339). Сначала выбирается направление, затем при необходимости запрашивается email. Для обоих направлений используется один affiliateId; ссылки сохраняются отдельно и могут использоваться одновременно. Ранее выданные ссылки и сохранённые ссылки в роликах не заменяются при выборе другого направления.

В конфигурации доступны `tracknow.exchange_campaign_id` и `tracknow.cards_campaign_id`. По умолчанию это 338 и 339, поэтому уже заполненный CONFIG_TOML не обязательно менять. `tracknow.campaign_id` оставлен для импорта старой кампании; укажите 0, если её больше не нужно опрашивать.

Импорт поддерживает правила существующих кампаний: CPA `card_open` ($10), CPS `card_top_up`, `card_withdrawal`, `chargeback`, `exchange` (0,1%). Нулевая комиссия `card_blocking` не создаёт начисления. События разделяются по campaignId и стабильному ID, а подтверждённые доходы обеих кампаний суммируются по источникам. Конфигурация кампаний в Tracknow автоматически не меняется.

## Материалы для пополнения рублями

После email и успешной выдачи ссылки CinCin Cards бот отправляет два видео из `assets/cards/`: `banner.mp4` и `card.mp4`. При повторном выборе Cards материалы также доступны, создавать аккаунт заново не требуется. Кнопка «Материалы» выдаёт все три уникальных видео. После выдачи партнёрской ссылки отправляется набор выбранного направления. Для Exchange выдаётся отдельный набор видео для пополнения криптовалютой.

Файлы отправляются альбомом, Telegram file_id кэшируется в базе отдельно для каждого бота и версии файла. При сбое выдачи ссылка остаётся сохранённой, пользователю предлагается повторная загрузка.

## Материалы для пополнения криптовалютой

После получения ссылки CinCin Exchange автоматически выдаются `assets/exchange/banner.mp4` (CinCin Banner_1_1.mp4) и `assets/exchange/card.mp4` (CinCin_card_1.mp4). Повторное скачивание доступно из «Материалы» и сообщения со ссылкой. Выбор направления сохраняется при повторной загрузке; баннеры Exchange и Cards не смешиваются.

## Общий раздел материалов

«Материалы» сразу отправляет альбом из трёх уникальных видео: баннер Cards, баннер Exchange и общий ролик о карте. Старое изображение и обработчик замены PNG удалены. Автоматическая отправка после получения ссылки по-прежнему содержит два файла соответствующего направления.

## Принятие условий и сохранение данных

Принятие условий сохраняется в SQLite с датой и не запрашивается повторно у уже согласившегося пользователя. «📋 Условия пользования» открывает текст для повторного просмотра. На Railway подключите постоянный Volume к сервису (рекомендуемый путь `/app/data`), иначе база может сбрасываться при обновлении контейнера. Бот автоматически использует путь подключённого Volume; подробности в SETUP.md.
